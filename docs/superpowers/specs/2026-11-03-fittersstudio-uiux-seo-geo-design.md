# 핏터스 스튜디오 UI/UX · 디자인 · SEO/GEO 개선 설계

작성일: 2026-11-03 · 대상: fittersstudio.com (Next.js 14 App Router, Tailwind, next-intl ko/en)

## 1. 왜 하는가

- 사이트의 기능(1RM 계산기, WOD 타이머, WOD 라이브러리 82개, 무브먼트 가이드 15개, 대회 일정, 드랍인 지도)은 갖춰졌다. 지금 부족한 것은 **첫 화면에서 바로 쓰게 만드는 흐름**, **기억에 남는 시각적 정체성**, **검색과 AI 답변에 인용될 만한 콘텐츠 구조**다.
- 수익(애드센스)은 트래픽에 비례한다. 최근 7일 핏터스스튜디오 페이지뷰는 129회, 수익은 US$0.13이었다. 광고 설정보다 **방문자를 늘리고 머무르게 하는 것**이 수익에 가장 큰 영향을 준다.
- 한국 검색(“1rm 계산기” 노출 약 1,200회, 평균 7.8위)은 이미 반응이 있고, 미국에서도 “wod library”, “named wods” 같은 영어 검색어로 노출이 시작됐다.

## 2. 목표 / 비목표 / 반목표

**목표**
1. 모바일 첫 화면에서 핵심 도구(1RM, 타이머, WOD)를 바로 쓸 수 있게 한다.
2. 크로스핏 박스의 세계에서 나온, 다른 사이트와 헷갈리지 않는 디자인 체계를 만든다.
3. 한국어·영어 검색 노출과 클릭을 늘리고, AI 검색(구글 AI 개요·AI 모드, ChatGPT 검색, Perplexity)에 인용될 수 있는 콘텐츠 형태를 갖춘다.
4. 광고 수익을 유지하면서 사용성을 해치지 않는 광고 배치를 만든다.

**비목표**
- 백엔드(Supabase) 구조 변경, 결제·회원 등급 같은 새 비즈니스 기능.
- 네이티브 앱 개발.
- 카카오 로그인 재도입(사업자 요건 때문에 보류 중).

**반목표 (이렇게 되면 기능이 돌아가도 실패)**
- 화려해졌지만 도구가 느려지거나, 첫 화면에서 도구에 닿기까지 오히려 더 많이 스크롤해야 하는 것.
- 확인되지 않은 정보(대회 일정, 인물 이름, 통계)를 콘텐츠를 늘리려고 지어내는 것.
- 같은 문장을 페이지마다 찍어내서 구글이 얇은 중복 페이지로 판단하는 것.
- 애니메이션 때문에 숫자가 처음에 0으로 보이는 것처럼, 검색엔진과 접근성을 해치는 장식.

### 3-2. 디자인 진단

현재 디자인은 AI가 흔히 만드는 기본값과 상당 부분 겹친다. 기능은 좋은데 "어디서 본 듯한" 인상을 준다.

- 거의 검은 배경(#0D0D0D) + 빨강→분홍 그라데이션 하나만 강조색으로 쓴다.
- 모든 섹션 제목이 대문자 굵은 영어("MORE FEATURES", "BY THE NUMBERS")이고, 위에 "CROSSFIT & HYROX PLATFORM" 같은 대문자 라벨이 붙는다.
- 같은 모양의 둥근 카드가 반복되고, 모든 링크 끝에 "→", 모든 섹션에 스크롤 페이드인이 들어간다.
- 가운뎃점(·)으로 이어 붙인 설명 문구가 많다.
- 글꼴이 Noto Sans KR 하나뿐이라 숫자(기록·타이머·무게)가 많은 사이트인데 숫자에 개성이 없다.

## 4. 디자인 방향: "박스의 바닥과 칠판"

### 4-1. 콘셉트

크로스핏 박스에 들어가면 보이는 것에서 디자인을 가져온다.
- **고무 바닥**: 어두운 회색 바탕. 순수한 검정이나 푸른 기가 도는 검정이 아니라, 고무 매트처럼 약간 따뜻한 짙은 회색.
- **범퍼 플레이트 색**: 국제 규격 플레이트 색(25kg 빨강, 20kg 파랑, 15kg 노랑, 10kg 초록)을 **의미가 있는 색 체계**로 쓴다. 장식용 그라데이션 대신 정보를 구분하는 데만 쓴다.
- **화이트보드의 WOD**: WOD 상세는 박스 화이트보드에 적힌 오늘의 운동처럼 보이게 한다.
- **경기장 전광판**: 타이머·1RM 결과·기록처럼 숫자가 주인공인 곳은 경기장 전광판처럼 좁고 큰 숫자 글꼴을 쓴다.

**한 곳에만 과감하게**: 이 사이트에서 기억에 남을 요소는 **전광판 숫자**다. 타이머, 1RM 결과, 대회 D-day가 같은 숫자 글꼴과 크기 체계를 공유한다. 나머지(목록, 설명, 메뉴)는 조용하고 정돈되게 둔다.

### 4-2. 색 토큰

| 이름 | 값 | 쓰임 |
|---|---|---|
| rubber | #1E1F22 | 기본 바탕(고무 바닥) |
| rubber-raised | #2A2B2F | 패널·입력칸 바탕 |
| chalk | #F1EFEA | 본문 글자, 화이트보드 면 |
| plate-red | #E8321A | 브랜드 로고 색과 동일. 주요 행동 버튼, Girl WOD |
| plate-blue | #1F6FEB | Hero WOD, 정보 링크 |
| plate-yellow | #F5B700 | Open WOD, 경고·마감 임박 |
| plate-green | #1E9E5A | 진행 중·완료·스케일링 |

- 빨강→분홍 그라데이션은 로고와 첫 화면 한 곳에만 남기고, 버튼과 카드에서는 빼서 단색으로 바꾼다.
- WOD 종류, 대회 지역, 상태 표시에 플레이트 색을 일관되게 쓴다. 예: Girl=빨강, Hero=파랑, Open=노랑.
- 모든 글자색은 바탕 대비 WCAG AA(본문 4.5:1) 이상으로 맞춘다. 노란색 위 글자는 rubber 색을 쓴다.

### 4-3. 글꼴

| 역할 | 글꼴 | 이유 |
|---|---|---|
| 본문·UI(한/영) | Pretendard (가변) | 한글·영문이 함께 깔끔하고 굵기 폭이 넓다. 셀프 호스팅으로 로딩을 통제한다. |
| 숫자·전광판·짧은 영문 제목 | Barlow Condensed (600/700, Google Fonts) | 좁고 큰 숫자가 경기장 전광판 느낌을 준다. 고정폭 숫자(tabular-nums)로 타이머 흔들림이 없다. |

- 대문자 영어 제목과 대문자 라벨은 쓰지 않는다. 제목은 문장형("대회 일정", "Competitions")으로 쓴다.
- 글자 크기 체계(모바일 기준): 본문 16 / 보조 14 / 소제목 18 / 제목 24 / 페이지 제목 32 / 전광판 숫자 64~120.
- `globals.css`의 최소 16px 강제 규칙은 없애고, 보조 글자 14px를 허용한다. 본문은 16px를 유지한다.

### 4-4. 화면 구성 원칙

- 내용은 왼쪽 정렬한다. 가운데 정렬은 첫 화면 한 곳에만 쓴다.
- 카드를 줄인다. 같은 모양 카드의 반복 대신 목록·표·화이트보드 같은 내용에 맞는 형태를 쓴다.
- 링크 끝 "→"와 섹션마다 붙은 스크롤 페이드인, 카운트업을 없앤다. 움직임은 사용자 행동에 대한 반응(타이머 시작, 결과 갱신)에만 쓴다. 첫 화면에만 한 번의 등장 연출을 둔다.
- 키보드 포커스 표시, `prefers-reduced-motion` 존중(이미 있음), 터치 영역 44px 이상을 지킨다.

### 4-5. 기본값 점검 (frontend-design 기준으로 스스로 검토한 결과)

- 처음 떠올린 "어두운 배경 + 빨간 강조색 하나"는 지금 디자인과 똑같은 기본값이어서 버렸다. 대신 플레이트 4색을 의미 체계로 쓰는 것으로 바꿨다.
- "큰 숫자 + 작은 라벨 + 그라데이션"인 홈 통계 블록은 흔한 기본 처리라 없앤다. 숫자는 실제 도구(타이머·1RM 결과)에서 전광판으로 보여준다.
- 번호 매김(01/02/03)은 실제 순서가 있는 곳(무브먼트 수행 단계)에만 쓴다.

## 5. 화면별 설계

### 5-1. 홈 (가장 먼저)

```
[모바일]
┌──────────────────────────┐
│ 로고               ☰     │
├──────────────────────────┤
│ 무엇을 할까요?            │  ← 한 줄 제목(문장형)
│ ┌──────────────────────┐ │
│ │ 1RM 빠른 계산         │ │  ← 무게 입력 + 반복 선택 → 결과가 바로 옆에 전광판 숫자로
│ │ [ 100 kg ] [5회 ▼]    │ │
│ │        117 kg         │ │
│ └──────────────────────┘ │
│ [타이머 시작] [WOD 찾기]  │  ← 두 개의 큰 버튼
│ ─ 오늘의 벤치마크 ─        │  ← 화이트보드 스타일 WOD 1개(날짜별로 바뀜)
├──────────────────────────┤
│ (여기부터 광고 허용)        │
│ 다가오는 대회(D-day 3개)   │
│ 무브먼트 가이드 / 지도      │
└──────────────────────────┘
```

- 로고 타이핑 애니메이션과 큰 빈 공간을 없애고, 첫 화면 안에 1RM 빠른 계산을 둔다.
- "오늘의 벤치마크"는 날짜 기준으로 82개 중 하나를 고르는 방식이라 매일 내용이 바뀌고, 서버에서 렌더링된다.
- 통계 카운트업 블록은 없앤다(U3 해결).
- 첫 화면 안에서 인페이지 광고가 뜨지 않게, 애드센스 "제외 영역"에 홈 상단 블록의 선택자를 등록한다(코드에 고정 id를 부여). 좌우·하단·전면 광고는 그대로 둔다.

### 5-2. 1RM 계산기

- 기본 단위: 한국어·영어 모두 lb(소유자 결정: 한국 크로스핏 박스도 lb를 쓴다). 마지막에 고른 단위를 기억한다(localStorage, 실패해도 lb로 동작).
- 결과를 입력칸 바로 위의 전광판 영역에 고정한다. 모바일에서는 스크롤해도 화면 위에 결과가 따라온다.
- **플레이트 계산기 추가**: 목표 무게를 넣으면 바벨(20/15kg) 양쪽에 끼울 플레이트 조합을 플레이트 색으로 그려준다. 초기 기획 때 원했던 "바벨 계산기"이고, 검색 수요(바벨 무게 계산, plate calculator)도 있다.
- "PR 기록하기" 배너는 결과 아래로 옮긴다.
- 설명 섹션에 "원알엠", "PR 계산기" 같은 실제 검색 표현을 자연스럽게 포함한다.

### 5-3. WOD 타이머

- 숫자는 전광판 글꼴(Barlow Condensed)로 화면 폭에 맞춰 최대한 크게 표시한다. 가로 모드에서는 숫자가 화면을 채운다.
- 주소로 미리 설정할 수 있게 한다. 예: `/timer?mode=amrap&min=20`, `/timer?mode=fortime&cap=10`. WOD 상세의 "타이머로 이동"이 이 주소로 연결된다(U5 해결).
- 라운드 기록 버튼(AMRAP 중 탭하면 라운드 +1)을 크게 둔다.

### 5-4. WOD 라이브러리와 상세

- 목록: 종류 배지를 플레이트 색으로 바꾸고, 필터 바를 상단에 고정한다. 카드 대신 촘촘한 목록과 카드 중 고를 수 있게 한다.
- 상세: WOD 구성을 화이트보드처럼 보여준다(밝은 chalk 면 + 어두운 글자, 손글씨는 쓰지 않음). 목표 기록은 수준별로 표(Elite / Competitive / Recreational)로 정리한다.
- "이 WOD로 타이머 시작"(사전 설정 주소)과 "기록하기"를 화이트보드 바로 아래에 둔다.

### 5-5. WOD 생성기 (신규)

- 검색 수요("크로스핏 와드 짜주는 사이트")에 대응하는 새 도구.
- 입력: 시간(10/15/20분), 장비(바벨·덤벨·케틀벨·맨몸·박스·줄넘기), 형식(AMRAP/EMOM/For Time).
- 출력: 무브먼트 데이터와 WOD 데이터에서 조합한 운동 + 타이머 사전 설정 링크 + 스케일링 안내.
- 생성 규칙은 코드로 고정한다(AI 호출 없음). 결과는 저장하거나 공유할 수 있는 주소로 만든다.

### 5-6. 대회 일정

- HYROX 목록을 월별로 묶고, 국가·도시 검색을 추가한다.
- 대회마다 "캘린더에 추가"(.ics 파일) 버튼을 둔다.
- **대회별 상세 페이지**를 만든다. 예: `/competitions/hyrox-seoul-2026`. 날짜, 장소, 공식 링크, 마지막 확인일, Event 구조화 데이터를 담는다(S4·S5 해결).
- 상태 표시(예정·진행 중·종료)는 플레이트 색으로 구분한다.

### 5-7. 상단 메뉴 정보 구조

현재 7개를 목적별 4묶음으로 정리한다.

| 묶음 | 하위 |

| 도구 | 1RM·플레이트 계산기, WOD 타이머, WOD 생성기 |

### 6-2. 기술 SEO 할 일

1. sitemap `lastModified`를 실제 수정일로 바꾼다(데이터 파일 기준 고정값 또는 빌드 시각이 아닌 콘텐츠 날짜).
2. 대회 상세 페이지에 Event 스키마(이름, 시작·종료일, 장소, 주최, 공식 링크, eventStatus)를 넣는다. 해외 HYROX는 공식 일정표에 장소가 없으므로 location에는 도시·국가만 넣고, 장소명을 추측해서 채우지 않는다.
3. 무브먼트 페이지의 HowTo 스키마는 Article로 바꾸거나 남겨두되 기대하지 않는다.
4. WOD 목록에 ItemList 스키마, 도구 페이지는 WebApplication 유지.
5. 홈 통계 0 렌더링 제거(U3).
6. Core Web Vitals 점검: 글꼴 교체 시 `font-display: swap`과 서브셋, 홈 배경 이미지 크기 최적화.

### 6-3. 콘텐츠 할 일

- **HYROX 가이드**(신규, ko/en): 8개 스테이션, 디비전별 무게 표, 경기 규칙을 표로 정리하고 공식 출처를 링크한다. 확인된 정보만 쓴다.
- **한국 크로스핏 드랍인 가이드**(신규, 영어 우선): 여행자 대상. 예약 방법, 일반적인 드랍인 비용 범위(출처 있는 것만), 지도 링크. 경쟁이 약한 해외 검색어다.
- WOD 상세의 고유 콘텐츠: Girl·Hero WOD처럼 유래가 공개된 WOD는 확인 가능한 사실만 1~2문장 추가한다.

## 7. GEO 전략 (AI 검색 인용)

조사 결과 정리(출처는 문서 끝):
- 구글은 AI 개요·AI 모드에 **추가 요구사항이나 특별한 최적화가 필요 없다**고 밝혔다. 기본 SEO가 바탕이다.
- llms.txt는 구글 검색에 영향이 없다고 구글이 안내했고, 실제 AI 크롤러 요청도 거의 없다는 조사가 있다. 낮은 우선순위의 선택 사항으로만 둔다.
- 구조화 데이터가 인용에 직접 도움이 되는지는 출처마다 다르다. 리치 결과와 엔티티 명확화 용도로 유지한다.
- 공통적으로 권하는 것: 답을 먼저 쓰는 문장, 비교 표, 출처가 있는 수치, 최신 업데이트 표시, AI 크롤러 허용.

**할 일**
1. 각 도구·가이드 페이지 맨 위에 한 문장 정의를 둔다. 예: "1RM은 한 번에 들 수 있는 최대 무게이며, 이 계산기는 Epley 공식으로 추정합니다."
2. 비교·기준 정보는 표로 만든다. 예: 1RM 퍼센트 표, HYROX 디비전별 무게, WOD 목표 기록 수준, 타이머 모드 비교.
3. 대회·HYROX 정보에 "마지막 확인일"과 공식 출처 링크를 계속 표시한다(이미 대회 페이지에 있음).
4. 소개(About) 페이지에 운영자와 데이터 출처 원칙(공식 사이트 기준, 추측하지 않음)을 밝힌다.
5. robots.txt 전체 허용을 유지한다.

## 8. 광고 배치 원칙

- 첫 화면(모바일 기준 첫 스크롤 영역)에는 인페이지 광고를 두지 않는다. 애드센스 "제외 영역"으로 처리한다. 코드는 해당 블록에 바뀌지 않는 id(예: `#fs-hero-tools`)를 부여하고, 소유자가 애드센스 화면에서 그 선택자를 제외 영역으로 등록한다.
- 좌우 사이드 레일, 하단 앵커, 전면 광고는 유지한다(소유자 결정 사항).
- 도구 사용 중(타이머 실행 화면, 계산 입력 영역)에는 광고가 끼어들지 않게 같은 방식으로 제외한다.
- 정식 도메인(www.fittersstudio.com)에서만 광고 스크립트를 불러오게 한다(미리보기 주소에서 광고가 잡히던 문제).

## 10. 소유자가 결정할 것

1. 디자인 방향 "박스의 바닥과 칠판"(플레이트 색 체계 + 전광판 숫자)로 갈지. 시안을 먼저 보고 결정할 수 있다.
2. 브랜드 그라데이션(빨강→분홍)을 로고 주변으로만 줄이는 데 동의하는지.
3. 홈 첫 화면에서 인페이지 광고를 빼는 것(수익 영향 가능)에 동의하는지.
4. 진행 순서. 기본 제안은 1단계 → 2단계 → 3단계 → 4단계.

## 11. 구현자에게 맡기는 것 (작성자 판단)

- 글꼴 셀프 호스팅 방식, 정확한 색 대비 미세 조정, 컴포넌트 분리 방식. (Pretendard, Barlow Condensed 모두 SIL Open Font License라 상업적 사용 가능)
- 플레이트 계산기의 기본 원판 세트(kg: 25/20/15/10/5/2.5/1.25, lb: 45/35/25/10/5/2.5)와 바벨 무게 선택지.
- 다크 테마 하나만 유지한다(타이머·체육관 환경에 맞음). 라이트 테마는 이번 범위가 아니다.
- 오늘의 벤치마크 선택 규칙(날짜 해시 등), WOD 생성기의 구체적 조합 규칙(장비·시간 제약을 지키는 범위에서).
- 대회 상세 페이지 주소 규칙(기존 이벤트 id 재사용).
